# AgentOS settings in `vitul.conf.json`

Vitul stores desktop, mobile, and AgentOS project settings in one root
`vitul.conf.json`. Use `vitul agentos init` to create the file in an existing
project, or edit the `agentos` section generated by `vitul create`.

Process apps declare their build and launch configuration under `agentos`:

```json
{
  "schemaVersion": 2,
  "productName": "Example",
  "identifier": "com.example.app",
  "version": "1.0.0",
  "agentos": {
    "type": "process",
    "targets": ["agentos/arm64", "agentos/x64"],
    "execution": { "mode": "native" },
    "build": {
      "steps": [],
      "artifacts": [{ "from": "dist", "to": "web" }]
    },
    "run": {
      "command": "node",
      "args": ["server.js"],
      "port": 9627,
      "healthCheck": "/health"
    }
  }
}
```

Omit `agentos.execution`, leave its `mode` empty, or set it to `container` to
use the default container runtime. Only `mode: "native"` selects native host
execution. Native mode runs the process directly on the Linux host with full
host access and requires explicit high-risk consent plus the local account
password on install or update.

Native mode requires a process app. AgentOS currently rejects native manifests
that declare deployment, Host Providers, or `native.external-wayland`; Vitul
reports these combinations during config validation. The default container
mode remains required for those features.

For a hosted site, set `agentos.type` to `remote-web` and `agentos.web.url` to
an HTTPS address. Remote-web packages open the site in AgentOS's embedded CEF
window and do not package a local process.

Run `vitul agentos validate` before building. Use `vitul agentos inspect` to
review the projected app profile and declared AgentOS targets.
