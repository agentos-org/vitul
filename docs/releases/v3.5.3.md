# Vitul CLI 3.5.3

Changes since [v3.5.2](https://github.com/agentos-org/vitul/releases/tag/v3.5.2).

## Highlights

- New Vitul apps depend on `agentos-sdk-ts` `^2.5.1`. ModelKit exposes the
  optional `maxOutputTokens` response-generation limit on model metadata and
  accepts it when registering or updating app models.
- The generated project guide explains the field and its Gateway-dependent
  availability. The existing `createAgentOSClient()` interface remains compatible.
- New projects generated by Vitul CLI and `create-vitul-app` depend on Vitul
  CLI `^3.5.3`.

## npm package versions

The Rust preview CLI remains at `0.2.0`; the desktop runtime and JavaScript API
retain the `2.12.0` source baseline. See the [version map](https://github.com/agentos-org/vitul/blob/v3.5.3/docs/MAINTENANCE.md)
and [supported platforms](https://github.com/agentos-org/vitul/blob/v3.5.3/docs/SUPPORT.md).

## Verification and migration

On macOS ARM64, the Vitul CLI Rust tests and JavaScript template test passed.
A fresh generated React project was type-checked and built using the published
SDK `2.5.1` and a local CLI binary, with Node `26.12.0`, pnpm `12.4.2`,
TypeScript `6.0.3`, Vite `8.3.7`, and Rust `1.99.1`. A live Gateway was not
exercised; after publication, verify a fresh install using the npm CLI packages.

Existing projects retain their dependencies and lockfiles; update them
separately to adopt the new SDK. Older Gateways may omit `maxOutputTokens` even
when a model reports `contextWindowSize`.
