# Vitul CLI 3.5.0

Changes since [v3.4.0](https://github.com/agentos-org/vitul/releases/tag/v3.4.0).

## Highlights

- Generate separate macOS icon assets from ordinary square artwork, with transparent margins and a rounded silhouette applied to the complete artwork. Other platform icons keep their existing output behavior.
- Choose automatic adaptation or passthrough for macOS artwork. Custom ICNS files are used directly by default. Logo mode controls the foreground logo separately from its baseplate.
- Track the original icon source and generation settings; regenerate derived resources when either changes and project the correct paths into the desktop host configuration.
- Generated projects include an editable `app-icon.png` source master.
- New projects explicitly derive their macOS icon from that master despite the bundled template ICNS. Managed icons retain their recorded original source instead of falling back to a low-resolution bundle thumbnail.
- Apple Silicon macOS disk images now use the `arm64` filename suffix.
- Update the AndroidTone and WinTone examples with native runtime, deployment, session, and system tray improvements.

## Migration

- macOS DMG filename patterns must accept `_arm64.dmg` in place of `_aarch64.dmg`. Intel and universal DMG suffixes remain `x64` and `universal`.
- PNG/SVG-only projects automatically derive a macOS ICNS during desktop configuration projection. Use `bundle.macosIcon.mode: "passthrough"` or `vitul icon --macos-mode passthrough` for artwork that already includes macOS margins or a special silhouette.
- Existing custom ICNS files are preserved by default. To regenerate one from a PNG/SVG source, configure `bundle.macosIcon.mode: "auto"` and retain the original source artwork.
- The static ICNS compatibility geometry is based on a measured macOS system icon; it is not a claim of exact conformance to an Apple template. Icon Composer projects are not automatically generated from a PNG.

See the [macOS icon guide](../MACOS-ICONS-zh_CN.md) for configuration, source metadata, cache behavior, and Finder/Dock verification.

## Native CLI binding targets

- macOS: x64 and arm64.
- Windows: x64, x86, and arm64.
- Linux: x64 GNU/musl, arm64 GNU/musl, armv7 GNU, and riscv64 GNU.

CLI binding availability is separate from the [supported app platform matrix](../SUPPORT.md).

The release workflow builds native bindings with Rust stable and Node.js 22. It tests macOS and Windows bindings with Node.js 22 and 24, tests Linux GNU bindings, and runs startup smoke checks for Linux musl and armv7. The riscv64 binding is built but is not run by that workflow. Completion and checksums must be confirmed for the final release artifacts.
