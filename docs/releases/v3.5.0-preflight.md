# 3.5.0 发布准备记录

记录日期：2026-10-19（Asia/Shanghai）。

## 发布基线与版本

- 发布基线是 GitHub 上已经存在的 `v3.4.0`，指向 `fa6b9b330`。准备开始时的 `main` 为 `5f3ae180e`，其后续于 3.4.0 的两个提交构成此次功能更新。
- npm 已发布版本已核实为 CLI `3.4.0`、两个命令包装包 `0.4.0`；查询到的版本列表中没有 CLI `3.5.0` 或包装包 `0.5.0`。
- CLI 主包、11 个平台绑定包、绑定加载器和版本元数据统一为 `3.5.0`。
- `@litevar/vitul` 和 `create-vitul-app` 为 `0.5.0`，依赖 CLI `^3.5.0`。
- 新项目模板、脚手架实现及相关断言、workspace 示例与 fixture、锁文件和中英文维护文档同步更新。
- Rust CLI `0.2.0`、桌面 CLI 实现包 `3.0.0`、运行时/API `2.12.0` 和 AgentOS manifest schema `1` 保持各自的独立版本。

发布说明正文：[v3.5.0.md](v3.5.0.md)。CLI changelog 保留已发布的 3.4.0 记录，单独新增 3.5.0。

## 本地检查

工具链：Apple Silicon macOS、Rust/Cargo `1.94.1`、Node.js `24.19.0`、pnpm `12.4.2`。本机默认 pnpm 自动切换入口不可执行，检查使用了同版本的独立可执行文件和临时依赖缓存。

| 检查                                                                        | 结果                                                                    |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `cargo test -p vitul-cli --locked`                                          | 通过：16 项单元测试、16 项 AgentOS 集成测试                             |
| `cargo test -p vitul-desktop-cli --lib icon::tests --locked`                | 通过：11 项图标回归测试                                                 |
| `pnpm install --lockfile-only --frozen-lockfile --offline --ignore-scripts` | 通过：1107 项锁文件条目及依赖策略检查                                   |
| 两个包装包的 `npm pack --dry-run --json --ignore-scripts`                   | 通过：版本均为 0.5.0，各包含 README、命令入口和 package.json            |
| macOS ARM64 Node 原生绑定构建和 CLI JavaScript 测试                         | 通过：绑定构建成功，2 个测试文件中的 6 项测试通过                       |
| 干净生成项目的前端检查和构建                                                | 通过：安装依赖、TypeScript 检查、Vite 生产构建及图标投影                |
| CLI 主包的 `npm pack --dry-run --json`                                      | 通过：3.5.0、13 个文件，包含新加载器和配置 schema；原生绑定由平台包分发 |

干净项目首先确认生成的 CLI 依赖为 `^3.5.0`；因为该版本尚未发布，安装检查将其临时改为本地 3.5.0 绑定链接，其余依赖通过 pnpm 安装，最终一次从缓存离线重建。该次生产构建使用 TypeScript `6.0.3`、Vite `8.3.4`、React `19.3.1` 和 `agentos-sdk-ts` `2.1.0`。随后模板依赖更新为 `agentos-sdk-ts ^2.2.0`；需在发布前用新版本重新完成干净项目安装、类型检查和构建。正式发布后的真实 npm 安装检查仍需执行。

准备过程中修复了两项默认来源问题，并加入回归验证：新项目显式从 `app-icon.png` 自动派生 macOS 图标，避免模板 ICNS 阻止适配；已受管理的 ICNS 优先使用来源记录中的原始素材，避免被 bundle 列表中的低分辨率 PNG 替换。端到端检查还确认 macOS 投影不会改写 Windows ICO。

## 正式发布时执行

1. 审阅并提交发布准备改动，同步 GitHub 与 GitLab，记录最终发布提交。
2. 确认该提交的必需 CI 检查通过，尤其是 AgentOS ARM64 包 smoke；本地检查不替代 Windows、Linux、Intel Mac 和真实 AgentOS 主机验证。
3. 对图标变更完成真实 macOS `.app` 的 Finder/Dock 对照检查，区分静态图标产物和系统缓存。此前通过的像素、格式和投影测试不能证明 Finder/Dock 的最终视觉效果。
4. 从审核后的提交创建 `v3.5.0` tag，并同步两个远端；以 `v3.5.0.md` 作为 GitHub Release 正文。
5. 运行 `publish-cli-js.yml`，选择 **v3.5.0 tag** 为工作流 ref，并填入该 GitHub Release 的数字 ID。工作流检出源码跟随所选 ref，发布时应固定到发布 tag。
6. 等待原生绑定构建、测试、npm 发布和 Release 资源上传完成。核对 11 个目标资源，从最终下载资源计算并上传 `SHA256SUMS`；校验和必须来自最终发布产物。
7. 确认 npm 上 CLI `3.5.0` 可安装后，在 **v3.5.0 tag** 上运行 `publish-vitul-commands.yml`，选择 `all` 发布两个 `0.5.0` 包装包。
8. 在干净目录验证 npm 已发布包的安装、`vitul --help`、项目创建和前端构建，核对下载资源校验和。

此记录是发布准备材料；检查结果只覆盖明确列出的本地环境。正式 tag、GitHub Release、跨平台产物和 npm 包由上述发布流程生成。
