# Vitul CLI 3.5.2

Changes since [v3.5.1](https://github.com/agentos-org/vitul/releases/tag/v3.5.1).

## Highlights

- New Vitul apps depend on `agentos-sdk-ts` `^2.5.0`. The existing
  `createAgentOSClient()` interface remains compatible.
- The generated project guide covers HarnessKit skill discovery and selection,
  thread forking, subagent model-selection events, and the host-only boundaries
  for workspace and skill-library administration.
- New projects generated by Vitul CLI and `create-vitul-app` depend on Vitul
  CLI `^3.5.2`.

## npm package versions

| Package                                                 | Version |
| ------------------------------------------------------- | ------: |
| `@litevar/vitul-cli` and its 11 native binding packages | `3.5.2` |
| `@litevar/vitul`                                        | `0.5.2` |
| `create-vitul-app`                                      | `0.5.2` |

The Rust preview CLI remains at `0.2.0`; the desktop runtime and JavaScript API
retain the `2.12.0` source baseline. See the [version map](https://github.com/agentos-org/vitul/blob/v3.5.2/docs/MAINTENANCE.md)
and [supported platforms](https://github.com/agentos-org/vitul/blob/v3.5.2/docs/SUPPORT.md).

## Verification and migration

The Vitul CLI tests and JavaScript template test passed on macOS. A fresh React
project was installed with the published AgentOS SDK `2.5.0`, type-checked,
and built with the SDK included in its frontend bundle. AgentOS host behavior
and the new HarnessKit methods were not exercised against a live Gateway.

Existing projects retain their dependencies and lockfiles; update them
separately to adopt the new SDK. Scoped thread forking and host-only management
restrictions require an updated Gateway.
